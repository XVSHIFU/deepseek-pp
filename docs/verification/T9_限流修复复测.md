# T9 限流修复：本机复测

此包用于验证网页模型请求节流；尚未完成真实网页稳定性验收，不替换正式 Release。

## 更新

1. 保留现有扩展 ID、配对及会话。先备份原扩展目录，再把本包 Chrome 扩展解压内容覆盖到原加载目录。
2. 在 Chrome 扩展管理页点“重新加载”，刷新已登录的 DeepSeek 页面。由编排 agent 安装配套 DSH 插件并重启 Harness；两端都更新后再测试。
3. 扩展 **设置 → 本机 Harness → 模型请求最小间隔（秒）** 保持默认 **5**。开启 Service Worker 的 Network → 保留日志，筛选 `completion`。

旧配对设置自动读取并补足默认间隔，无需重新填写令牌。保存设置后会写入新版配置；不要直接回退旧扩展继续使用新版配置，回退应使用备份和配套组件。

## 谁来测试

你完成重新加载并告诉 agent；agent 新建只读会话、发送人工诊断任务，不使用旧失败链、不改项目文件。真实请求之间自动等待，不需要你手动控制速度。

先空闲至少 60 秒，再以 5 秒间隔做至多 12 次网页模型请求；首次限流立即停止。本轮若需要第二档，充分冷却至少 120 秒后改为 10 秒，另做至多 6 次。不会并发冲击、更换账号或持续试探更短间隔。两批都通过也只说明本次样本稳定，不是 DeepSeek 官方限额。

记录 Network 请求开始时间间隔及成功/限流结果即可；不要导出 HAR 或发送请求头、令牌、请求载荷。

## 预期表现

- 连续工具任务会慢一些；已有模型响应耗时足够长时不会再额外加固定等待。
- 限流时显示中文原因并暂停，已完成工具结果保留；连续限流的冷却为 30 / 60 / 120 秒。
- 等待可以取消。旧失败链仍隔离，不自动重跑已执行工具；核对进度后可用官方新建/分支会话继续。
- 节流只覆盖当前扩展连接的 Harness 会话，不能控制别的浏览器或直接在 DeepSeek 网页中的发言。
